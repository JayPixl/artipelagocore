# Quest tracking as a hard FTB patch with server-team Global store

The `questtracking` module takes a hard dependency on FTB Quests, Teams, and Library and patches progress resolution via mixins on `TeamData.setProgress` (plus quest/task `writeData`/`readData`, `writeNetData`/`readNetData`, `fillConfigGroup` legs), because Solo and Global tracking require rerouting the single write choke point and persisting a per-quest/per-task flag through reloads and editor saves. Global progress is pooled on a fixed-UUID FTB server team fanned out to all teams (toasts to everyone online), rather than a custom SavedData store, so save/load and client sync reuse FTB's existing paths. Rejected alternatives: soft-optional integration, driving built-in tasks externally without patching, and a bespoke global store.
